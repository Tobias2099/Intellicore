# Docker Development Environment

The Docker stack supports the required research toolchain:

- Supabase cloud Postgres connectivity checks
- Python 3.11 service runtime
- CPU PyTorch for MARL training
- C++ compiler, CMake, Ninja, and gdb
- gem5 build dependencies such as SCons, protobuf, Boost, zlib, m4, lld, and gperftools
- gem5 execution from the pinned `gem5/` Git submodule

## Commands

```bash
cp .env.example .env
git submodule update --init --recursive gem5
docker compose --profile dev build dev
docker compose --profile gem5 run --rm gem5-init
docker compose --profile gem5 run --rm gem5-shell
docker compose exec dev bash scripts/docker-smoke.sh
docker compose exec -e MIGRATION_MESSAGE="describe schema change" dev python scripts/auto_migrate.py
docker compose --profile tools run --rm -e MIGRATION_MESSAGE="describe schema change" supabase-auto-migrate
docker compose --profile tools run --rm -e MIGRATION_MESSAGE="describe schema change" -e ALLOW_DESTRUCTIVE_MIGRATIONS=true supabase-auto-migrate
docker compose --profile tools run --rm supabase-migrate
docker compose --profile tools run --rm supabase-check
docker compose --profile tools run --rm supabase-orm-check
```

Prefer `docker compose exec dev ...` for repeated service commands because it reuses the already-built dev container and does not reinstall Python dependencies each time. The `supabase-*` tool services are best for clean one-shot CI-style runs.

`scripts/auto_migrate.py` refuses to apply destructive or risky autogenerated operations unless `ALLOW_DESTRUCTIVE_MIGRATIONS=true` is set. Use that override only after reviewing the generated Alembic revision.

## gem5 Submodule Workflow

gem5 source is tracked through the top-level `gem5/` submodule. The old `gem5-prebuilt` image workflow is deprecated; Docker now provides the Linux build environment, while the submodule is the single source of truth for gem5 source.

Initialize or refresh the submodule:

```bash
git submodule update --init --recursive gem5
```

Build gem5 from the submodule:

```bash
docker compose --profile gem5 run --rm gem5-init
```

That command stores the build output in Docker's `gem5-build` volume mounted at:

```text
/workspace/gem5/build/X86/gem5.opt
```

Open an interactive gem5 shell:

```bash
docker compose --profile gem5 run --rm gem5-shell
```

Inside the container:

```bash
$GEM5_ROOT/build/$GEM5_ISA/$GEM5_BUILD_VARIANT --help
```

Run the baseline architecture config:

```bash
docker compose --profile gem5 run --rm gem5-shell bash -lc \
  'cd "$GEM5_ROOT" && build/${GEM5_ISA:-X86}/${GEM5_BUILD_VARIANT:-gem5.opt} --outdir=/workspace/m5out/intellicore-arch /workspace/configs/gem5/architecture.py'
```

Editing files under `configs/gem5/`, `benchmarks/`, or `sim/` does not require rebuilding gem5. Rebuild with `gem5-init` only when the gem5 submodule source changes, the selected ISA or binary variant changes, or the `gem5-build` volume/build output is missing.

To intentionally update gem5, update the submodule commit and commit the new parent-repo submodule pointer:

```bash
cd gem5
git fetch --tags
git checkout <tag-or-commit>
cd ..
git add gem5
```

## Services

- `dev`: Long-running development container with Python 3.11, CPU PyTorch, C++ build tools, and gem5 build dependencies.
- `gem5-shell`: Interactive shell using the dev image with `GEM5_ROOT=/workspace/gem5`.
- `gem5-init`: One-shot build helper that compiles gem5 from the `gem5/` submodule into the Docker `gem5-build` volume.
- `gem5-architecture`: One-shot baseline architecture run using the submodule build.
- `supabase-check`: One-shot database schema check container that verifies the Supabase telemetry database schema through `DATABASE_URL`.
- `supabase-auto-migrate`: One-shot workflow that upgrades to head, detects SQLAlchemy model changes, generates a migration if needed, applies it, and runs checks.
- `supabase-migrate`: One-shot migration container that runs `alembic upgrade head`, then runs schema and ORM checks.
- `supabase-revision`: One-shot migration generator that runs `alembic revision --autogenerate` and writes a new file under `infra/db/alembic/versions`.
- `supabase-orm-check`: One-shot SQLAlchemy smoke test that inserts, reads, and deletes a temporary simulation run.
